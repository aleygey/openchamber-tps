## 1.2.1 修复了什么

1.2.0 虽只在生成片段到达时累计“活跃平均”，但使用的实时 TPS 仍然是“过去五秒字符数 / 固定五秒”。短输出、每次工具结束后的输出，以及未填满五秒的窗口，都可能被空闲时间稀释。只过滤 `busy` 或把工具期间的零值从图上隐藏，不能修复这个分母。

1.2.1 将实时值、平均、峰值、曲线和上一轮平均统一到**已观测到的 LLM 生成区间**：

- **实时 TPS**：当前连续片段内，最近至多五秒的已计时 Token 估算量 / 对应实测时长。只有一秒数据就除以一秒，不固定除以五秒。工具、步骤、重试、授权/提问、文本片段结束等明确边界会断开区间。
- **生成平均**：所有已计时区间的 Token 估算量之和 / 这些区间时长之和。不再对有偏的五秒读数求平均，也不是整个 Agent 任务的耗时平均。
- **生成峰值**：上述有效生成窗口中的最大 TPS。至少观测到 250ms 才产生窗口读数；短窗口仍较易波动，不应当作服务端峰值基准。
- **执行工具期间**：当前 TPS 显示 `—`，状态为“执行工具”；平均、峰值和曲线保持，不持续补零。收到新的生成片段后才恢复采样。
- **首个片段**：只建立时间锚点，不能知道它在到达前花了多少生成时间，因此不把该片段本身的字符数塞进后续已计时区间。单片段返回或尚无足够时间跨度时显示“采样中”，不伪造 1ms 分母。

例如两个已计时片段各生成 100 Token、各耗时 1 秒，中间 bash 运行 60 秒，生成平均应为 `200 / 2 = 100 tok/s`，不是 `200 / 62`。仓库测试用合成流验证工具等待从 0ms 到 5 分钟时，恢复后的实时值与累计均值保持一致。

### 哪些输出算 LLM 生成

计入 `session.text.delta`、`session.reasoning.delta` 和 **`session.tool.input.delta`**：LLM 写 bash 命令/工具参数 JSON 本身也是生成。**不计入** bash 真正执行的耗时、stdout/stderr、`session.tool.progress`、工具结果和历史完整快照。

工具调用使用 OpenCode 2 的 `session.tool.called/success/failed`，并处理 `session.shell.started/ended`。后台工具未结束时，若模型仍确实发来生成增量，这些真实增量照常测量；工具进度通知不冒充 LLM Token，也不反复打断并行生成。

不再把“片段间隔超过 1 秒”一律删掉：没有明确工具/等待边界的慢速生成或网络停顿会保守计入接收间隔，避免把慢模型人为算快。超过两秒没收到片段时，界面暂时显示等待，不靠网页轮询持续追加数据；若之后仍是同一未断开的片段，那个接收间隔仍有可能包含网络停顿。

### 这仍然是估算

流式增量是字符，不是逐 Token 时间戳。默认每字符 0.25 Token，按已结算步骤的 `tokens.output + tokens.reasoning` 逐步校准**后续**字符估算。计入工具参数后，校准分母也包含对应生成字符。

真实 usage 的会话总 Token 仍单独显示；不会把整步真实 Token（可能含未观测/隐藏的内容）直接除以只观测到一部分的时间。实时、生成平均、生成峰值、上一轮生成平均均标记 `≈`。不将旧样本追溯重分词，也不声称这些值就是模型服务端内部解码 TPS。

首字延迟、排队和请求预处理不计入生成吞吐量。本统计并非全任务性能：模型服务、网络缓冲、隐藏推理、不同语言分词以及晚接入事件流都会影响估计。缺少匹配增量时宁可显示无样本，也不从一份完整历史文本伪造速度。

## 图表与保存

图表仍在 Work Status 小卡片内，可折叠，支持近60秒、近5分钟和全部保留，悬停查看钟表时间。横轴为累计已观测生成时间，明确暂停以断线表示，虚线是整个已记录会话的生成平均。图表范围不改变累计平均/峰值。

统计按 origin + session ID 隔离。之前打开过的会话在同一服务的全局事件流运行期间继续独立采集；未访问的会话不自动采集。每会话保留1800个图点，最多100个会话，裁剪图点不丢累计平均和峰值。

**本次更换了统计口径，旧数值不能无损换算。** 新统计从更新后开始，保存在：

```text
~/.local/share/openchamber-tps/metrics-v2/
```

旧的 `metrics-v1/` **保留原样，不删除、不混入新平均**。新目录使用 schema 2，避免将旧五秒均值冒充生成速率。安装前、停机或丢失的事件不做回填。首次更新看到空图是正常的；完成一段生成后会有新数据。

文件只含数值和时间，不含提示词、回复、原始事件、模型 API Key、密码、Cookie 或原始会话名。哈希文件名，目录新建权限0700、文件0600，约每五秒原子保存，正常退出再保存。异常退出可能损失未保存的近期数据；写盘失败提示并退化为内存统计。重启可恢复已保存的新口径记录，但重新连接后的间隔不会算作生成。

完整面板“重置本会话统计”仍需再次点击确认，只清当前会话新增的统计与曲线，不删除 Agent 消息或登录状态。卸载不会自动删除独立统计目录。

## 认证与兼容

目标为 Windows OpenChamber **2.1.1** 前端直接连接 Linux Server、OpenCode 2 全局 SSE。原认证修复已获用户实机确认；本次计量修复仍需用户环境验证。

收到401后，卡片让用户明确输入 `--ui-password` 对应的现有访问密码，通过官方 `POST /auth/session` 获取会话 Cookie。密码仅用于登录、不保存，Cookie 只在扩展服务内存里并绑定准确 origin。接口使用主程序的 `serviceRequest` 代理，扩展服务仅监听127.0.0.1，所有入口检查服务 Bearer Token。登录和事件流不跟随重定向，不跳过 TLS 验证；HTTP 登录仍要求确认可信网络。

公共 Relay、企业单点登录、仅客户端凭证认证、自定义 Cookie/改端口代理以及多个独立服务进程同时写同一统计目录仍未验证。新功能不增加读取聊天文件或保存认证凭据的权限。获准的本地服务具有运行用户的系统权限，不是操作系统沙箱。
