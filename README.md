# OpenChamber TPS Meter

当前维护版 **1.3.0**，分支 `fix/ui-password-auth`。目标：Windows OpenChamber 2.1.1 前端直接连接 Linux Server。不是上游官方发布版。

## 安装或更新

在 Windows 当前连接 **Cloud-Desktop** 的窗口中，打开 **Settings → Extensions → Check for updates → TPS Meter → Update**，确认版本为 **1.3.0**。安装地址不变：

```text
https://github.com/aleygey/openchamber-tps#fix/ui-password-auth
```

首次安装时，在 **Folder, ZIP, or URL** 填入完整地址并点击 Add。保留 `#fix/ui-password-auth` 后缀；`main` 仍是上游版本。审阅并批准服务权限；同一个 `tps-meter` ID 不要并装。

无需 npm install、Bun 或重新编译主程序。保留服务器密码；更新重启扩展服务后可能需要重新登录。已有 `metrics-v2` 历史无需删除，继续读取。

如果之前改成了文件夹或 ZIP 安装，请在扩展设置里移除那一条，再用上述 Git 地址添加，才能继续通过 Git 检查更新。移除扩展不会主动删除独立的统计目录。

GitHub 不可访问时，也可将安装包解压到 Linux，在扩展页面填入 Linux 扩展根目录的绝对路径（目录下直接包含 `package.json`）。文件夹安装不跟随 Git 自动更新。

本次提交保留远端原有测试，新增显示层测试；附带的定向检查结果只代表本次实际重新运行的 23 项，未将其他旧测试计入通过数量。

## 极简界面

Work Status 默认只显示 **`≈ 132 tok/s`、小状态点、细曲线** 和一个 `⋯` 详情按钮。默认高度约100px（离线浏览器测试约90–125px），不显示坐标轴、累计时间、统计标题和解释文字。

点击 `⋯` 展开原始生成平均、峰值、曲线范围、重试、清除登录和重置统计。默认看最近60秒的累计生成时间，可切换近5分钟或全部保留。状态点悬停/键盘聚焦时可查看状态；曲线悬停查看时间和带“平滑”标记的估算值。完整独立面板仍提供坐标轴和诊断信息。

工具运行、等待模型、断线或未登录时，实时值为 `—`，不会用0冒充测得的速度。平均、峰值、已记录曲线保留。登录和错误提示不会为了简洁而隐藏。

## 平滑是显示层，不改测速分母

1.2.1 在文本、推理、工具参数、步骤、工具等边界断开计时。旧图直接把每个边界画成断线，因此短片段也显得零碎；断线本身并不证明工具耗时被计入。

1.3.0 增加独立的 `ui/presentation.js`：

- 曲线在已观测生成区间上按250ms重采样，再做时间归一化EMA（250ms时相当于alpha=0.3）。长历史自适应降低显示采样密度，避免生成过多图点。
- 已标记边界的省略间隔不超过1.2秒时做显示连接；1.2–2.5秒使用淡虚线；超过2.5秒保留断线和小刻度。只连接已有端点，**不在暂停期间生成数据或增加累计生成时间**。
- 线段使用不超出相邻端点数值范围的平滑绘制；不会由曲线插值凭空制造峰值。
- 当前大数字按1.5秒时间常数平滑。重复轮询同一数据不重复更新EMA；约1.2秒无新测量后显示等待。明确的工具、授权、断线等状态立即停止显示当前速度。
- 平均、峰值、保存文件继续使用原始生成区间数据，不采用平滑值。图与数字是趋势展示，可能滞后于突变。

**没有采用“间隔超过1.2秒就从原始统计中删掉”的算法。** 没有明确边界的慢速模型输出或网络停顿仍保守计入接收间隔，避免把慢模型算快。短间隔阈值只影响显示，不表示供应商真实解码时间已知。

## 保留的统计口径

原始实时TPS使用当前连续生成片段最近至多5秒的估算Token数除以对应实测时长；生成平均为所有匹配区间的估算Token总数除以累计生成时间，峰值为有效生成窗口的最高值。单片段仅建锚点，少于250ms不显示有效窗口速率。

计入文本、推理和LLM生成工具参数JSON的增量；不计Bash运行、工具结果、进度、stdout/stderr、首字等待或明确的授权/提问等待。后台工具与LLM并行时仍统计实际的模型增量。字符数按步骤usage逐渐校准，所有TPS仍为客户端估算，不能当作服务端逐Token解码基准。

## 历史与认证

继续使用 `~/.local/share/openchamber-tps/metrics-v2/` 和schema 2，不迁移、不清空1.2.1数据。每会话最多1800图点，最多100会话；裁剪曲线不丢累计平均/峰值。按服务器origin与session ID隔离，约每5秒保存数字和时间，不记录对话、原始事件、密码或Cookie。未安装、停机和断线期间的数据不能补回。旧 `metrics-v1` 保留但不混用。

登录仍通过 `POST /auth/session`，使用现有OpenChamber UI密码。密码不保存；Cookie仅在扩展服务内存里，绑定准确origin，不跟随重定向。HTTP登录仍需明确确认可信网络。扩展只监听回环地址，所有服务接口需要主程序分配的Bearer凭据。不要关闭服务器认证。

## 验证与限制

本次运行的23项定向Node测试与离线沙箱UI检查通过，详见 `TEST-REPORT.md`。这不是用户实际Windows/Linux环境的端到端验证。

公共Relay、企业SSO、改Cookie/端口的复杂代理、多独立服务进程同时写目录仍未验证。网络缓冲、隐藏推理、缺失事件、不同分词比例都可能影响估算；平滑不会提高tokenizer精度。
