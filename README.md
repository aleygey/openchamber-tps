# OpenChamber TPS Meter — 认证、会话统计与活跃曲线

当前版本：**1.2.0**。这是 `aleygey/openchamber-tps` 的维护分支，不是上游官方发布版。

保留 Work Status 紧凑卡片、完整 TPS 面板及 `1.1.1-auth.1` 的 UI 密码认证。新增按会话记录的平均 TPS、最高 TPS，以及只展开活跃时段的变化图。运行时代码是可直接加载的 JavaScript，没有第三方运行依赖，也不需要重新编译 OpenChamber。

## 安装或更新

在连接目标 Linux 实例的 Windows OpenChamber 中打开 **Settings → Extensions**。已通过下面地址安装的用户，点击 **Check for updates → Update**，确认卡片版本为 `1.2.0`：

```text
https://github.com/aleygey/openchamber-tps#fix/ui-password-auth
```

首次安装时把完整地址填入 **Folder, ZIP, or URL**，点击 **Add**，审阅并批准运行本地服务权限。同一个 `tps-meter` ID 不能与原版并装；`main` 不是这个维护分支，不要漏掉后缀。

回到 **Work Status → TPS**。更新可能重启扩展服务，所以可能需要再输入一次原来的 OpenChamber UI 密码。无需关闭服务器密码、修改启动参数或安装 npm/Bun 依赖。

GitHub 无法访问时，在可访问的机器获取分支，再复制到 Linux；在扩展设置中填入 Linux 扩展根目录的绝对路径。文件夹或 ZIP 安装不能通过 Git 更新：先停用扩展，替换文件，再重新启用。

```bash
git clone --branch fix/ui-password-auth --single-branch \
  https://github.com/aleygey/openchamber-tps.git \
  "$HOME/openchamber-tps-auth"
realpath "$HOME/openchamber-tps-auth"
```

## 新增统计

**活跃平均**与**最高（5秒）**始终显示在实时数值下面。图表可以在卡片内展开或收起；不需要为了看曲线打开独立大面板。选择 **近60秒、近5分钟、全部保留**，鼠标停在曲线上可以查看对应时刻、累计活跃时间和 TPS。

平均值和峰值是不同的统计口径：

- **实时 TPS**沿用原版：最近 5 秒字符数乘以当时的 Token/字符估算比例，再除以 5 秒。包含文字与推理，不统计工具输入 JSON。
- **活跃平均 TPS**对连续生成时段中的上述滚动 TPS 做**时间加权平均**。不是对网页刷新出来的数字直接求平均，也不是整场 Agent 任务的 `总 Token / 总耗时`。不同时长的片段不会获得相同权重。
- **最高 TPS**是收到流式输出时观测到的**5 秒滚动 TPS 最高值**，不是单 Token 的瞬时尖峰；空闲后不会归零。
- **上一轮平均速率**仍保留在完整面板中。这是原有的步骤 Token 结算口径，与新增的“活跃平均”不是同一个指标。

活跃时间由相邻流式片段的到达间隔估算：同一 assistant message 内，相邻片段间隔不超过 1 秒才累计；明确的工具、权限、提问、步骤/执行边界会断开区间，较短的明确等待也不会被计入。超过 1 秒的间隔、断线和进程重启的时间不累计。因此它是**客户端观测估算**，不是供应商内部解码速度；网络缓冲、慢速分片、分词比例和未完整观测的步骤都会影响结果。

只有一个片段、尚没有可测时长时，平均值显示 `—`，不会用 1 毫秒硬凑一个很高的数值。平均、峰值和图中的 `≈` 都明确表示估算。

## 曲线怎么看

横轴为**累计已观测到的活跃时间**，不是钟表时间。等待和工具执行期间不会填一长串零值把图压扁，而是在下一段输出开始时断开曲线。悬停提示仍保留原来的钟表时间。

图上的虚线是整个已记录会话的活跃平均；切换“近60秒/近5分钟”只改变图表显示范围，不改变顶部会话累计平均和峰值。图表约每秒更新，实时数字约每 250 毫秒刷新。记录由扩展服务处理，不依赖浏览器刷新次数。

历史点大约按每个活跃秒保留一个，额外保留分段起点与当前端点；每会话最多 **1800 个点**，超过后只丢弃最旧的图表点。会话平均和最高仍覆盖全部已记录区间，不因图表裁剪而重置。

## 保存与会话切换

统计按 **服务器 origin + session ID** 隔离。切换会话不会把 A 的数据算到 B，也不会清空 A 的累计统计。只要同一服务器的扩展服务和事件流仍在运行，之前在 TPS 中打开过的会话也会继续采集；从未打开过的会话不会自动采集。

在 Linux 端，数字统计保存在运行 OpenChamber Server 的用户目录下：

```text
~/.local/share/openchamber-tps/metrics-v1/<SHA-256>.json
```

文件名是服务器地址与会话 ID 的组合哈希，不包含原始项目名。文件只包含数值统计、时间和曲线点；**不写入提示词、回复文本、原始事件、模型 API Key、密码或 Cookie**。目录新建权限为 `0700`，文件为 `0600`；每 5 秒原子保存一次，正常退出时再保存一次。异常退出可能损失尚未保存的最近数据；写盘失败会提示并退化为内存统计，不阻断登录或实时读数。

最多保留 **100 个会话**的记录，超出后清理较旧记录。关闭浏览器卡片不会主动删除记录，服务重启后打开对应会话会恢复平均、峰值和曲线。但本功能不是一直在线的历史审计：服务停用、掉线或尚未开始采集的时间无法恢复，也**不会倒推安装前的会话 TPS 历史**。

完整 TPS 面板的 **重置本会话统计**需要在 5 秒内再次点击确认；只清空对应会话的新增统计和曲线，不清除别的会话、Agent 消息或登录状态。卸载扩展不会自动清除此独立的数字统计目录，需要删除时可在服务停用后手动清理。

## UI 密码认证保持不变

原版扩展服务没有主界面的 Cookie，直接请求 `/api/global/event` 会遇到 `401`。维护版在卡片内让用户明确登录：服务通过官方 `POST /auth/session` 获取 UI session Cookie 后，再订阅事件流。这里输入的是 `--ui-password` 对应的**OpenChamber 访问密码**，不是 Linux 密码、GitHub Token 或模型 API Key。

页面通过主程序 `serviceRequest` 通道请求扩展服务，不直接连接服务端口。密码提交后清空，不写入文件或浏览器存储；Cookie 仅在服务内存中持有，并绑定到准确的服务器 origin。登录失败不会自动反复重试密码；登录和事件流不跟随重定向，也不跳过 TLS 验证。

HTTP 登录仍需确认服务器和网络可信。HTTP 不加密，非可信网络应使用 HTTPS 或经批准的安全隧道。更新、服务重启或登录过期后可能需要重新登录；**统计文件可以保留，但密码与 Cookie 不会因此落盘**。

扩展服务仅监听 `127.0.0.1`，包括新增历史与重置接口在内的所有请求都需要主程序分配的服务 Bearer Token。获准的本地服务具有运行用户的系统权限，因此仍须信任扩展作者；这些声明不等于操作系统沙箱。

## 兼容与限制

目标为 OpenChamber **2.1.1** 与 OpenCode 2 全局事件流，适用于 Windows 前端直连 Linux Server。认证修复的前一版已得到用户实际使用确认；本次新增功能仍需在用户实际环境验证。

公共 Relay 的 `srcDoc` origin、企业单点登录、仅客户端凭证认证、自定义 Cookie 名，以及修改内外端口的反向代理仍未验证。不同服务器地址即使最终指向同一实例也使用不同记录，不会自动合并。重启后只恢复数字历史，不自动重放过去的事件。
